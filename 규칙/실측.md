# FitShare 실측 과정 안내

이 문서는 사이트의 **현재 코드가 실제로 하는 일**을 설명해요. 아직 만들지 않은 기능은 맨 아래에 따로 적었어요.

## 한눈에 보기

`옷 정보 준비 → 배경에서 사진 촬영 → 사진 기울기 보정 → 옷 윤곽 찾기 → 길이와 너비 계산 → 사람이 확인 → 저장`

컴퓨터는 사진 속 픽셀을 보고 옷의 크기를 짐작해요. 그래서 줄자로 잰 기준값과 자동 측정값을 비교하고, 저장하기 전에 사람이 사진과 숫자를 확인해야 해요.

## 1. 네 가지 배경 비교 실험

### 시작하기 전에

1. 실험할 옷의 개수를 고릅니다. 1벌부터 30벌까지 고를 수 있어요.
2. 옷마다 이름, 종류, 줄자로 직접 잰 길이와 너비를 적습니다. 이 숫자가 컴퓨터 결과를 비교할 **기준값**이에요.
3. 촬영 순서를 정합니다. 순서를 바꿀 수 있지만, 실험에서는 네 배경을 모두 사용해요.
4. A0 배경 종이는 인쇄할 때 **실제 크기 100%**로 출력해요. “페이지에 맞춤”으로 줄이면 자로 잰 크기와 달라져요.

### 사진 찍는 순서

옷 한 벌씩, 선택한 배경 순서대로 찍어요. 화면에서 지금 어떤 옷과 배경을 찍을지 알려 줍니다. 사진첩에서 고르거나 카메라로 찍을 수 있어요. 배경의 기준 표식과 옷 전체가 사진에 들어오게 해 주세요.

현재 네 배경 비교 실험 화면은 사진을 브라우저에서 긴 변 최대 1200픽셀로 줄이고 JPEG 품질 0.82로 바꿔 서버에 보내요. 서버는 표식을 찾기 전에 긴 변을 최대 1000픽셀로 한 번 더 줄여요. 서버 분석에 연결되지 않으면 브라우저의 간단한 대체 분석을 시도할 수 있는데, 이 결과는 서버 분석이나 데이터셋 결과와 다를 수 있어요.

| 코드 | 배경 | 컴퓨터가 기준으로 보는 것 |
| --- | --- | --- |
| M1 | 동그란 점 배경 | 일정한 간격의 점. 점 사이 간격은 10cm예요. |
| M2 | 모눈 배경 | 격자 선이 만나는 곳. 작은 칸 간격은 5cm예요. |
| M3 | 테두리 표식 배경 | 가장자리에 인쇄된 ChArUco 표식의 번호와 모서리 |
| M4 | 네 칸 표식 배경 | 네 칸에 있는 ChArUco 표식의 번호와 모서리 |

### 사진에서 크기를 찾는 방법

1. **사진을 읽어요.** 촬영한 사진을 FitShare 서버로 보내 분석해요. 서버는 표식을 빨리 찾도록 긴 변을 최대 1000픽셀로 맞춰요.
2. **배경을 찾아요.** 점, 격자 교차점 또는 ChArUco 표식을 찾습니다. 표식 위치를 기준으로 비스듬한 사진을 정면에서 본 것처럼 펼쳐요.
3. **옷 부분을 찾아요.** OpenCV의 GrabCut과 색 차이를 이용해 옷일 것 같은 부분을 골라요. 사진에서 옷과 배경의 색이 비슷하거나 그림자·주름이 있으면 잘못 찾을 수 있어요.
4. **너비와 길이를 계산해요.** 옷 종류별 기준 위치를 따라 너비를 재고, 찾은 옷의 위쪽부터 아래쪽까지를 길이로 계산해요. 상의는 가슴 너비, 바지는 허리 너비를 찾아요. 여기서 너비는 옷을 바닥에 펼쳤을 때의 좌우 길이예요. 몸 둘레가 아니에요.
5. **cm로 바꿔요.** 사진을 A0 크기(가로 84.1cm, 세로 118.9cm)에 맞춘 뒤 픽셀 길이를 cm로 계산해요.
6. **사람이 확인해요.** 사진 위의 선이 옷에 맞는지 보고 숫자를 확인해요. 자동으로 못 찾으면 화면의 수동 도구로 모서리나 측정점을 고르고 숫자를 직접 고칠 수 있어요.

너비와 길이를 모두 잰 뒤에는 자동 측정값과 처음 줄자로 잰 기준값의 차이를 배경별로 비교해요. 오차가 작을수록 기준값과 가까운 결과예요.

## 2. 사진으로 옷을 등록하는 과정

옷 등록은 네 배경 비교 실험과 별도 화면이에요. 옷을 한 벌씩 등록합니다.

1. 옷 종류를 먼저 고릅니다. 현재 종류는 상의 외투, 흰 크롭티셔츠, 원피스, 점퍼, 바지예요.
2. 갤러리 사진을 고르거나 카메라로 찍어요. 사진은 현재 등록 화면에서 긴 변이 최대 3000픽셀이 되도록 줄이고 JPEG 품질 0.88로 다시 저장해요.
3. 서버는 현재 등록 화면의 고정 배경인 M4를 기준으로 사진을 펼치고, 옷 종류에 맞춰 길이·너비와 색을 찾아요.
4. 이름과 성별·공용 여부는 사람이 입력해요. 종류와 자동으로 찾은 숫자·색도 사진을 보고 고칠 수 있어요. 사진만 보고 성별이나 옷 종류를 자동으로 판정하지는 않아요.
5. 저장을 누르면 옷 정보와 사진이 실행 중인 서버 PC의 `server-data/garments/` 아래에 저장돼요. 지금은 옷장 카드에 배경 매트가 있는 사진이 보입니다.

### 등록 결과와 비교 실험 결과가 달랐던 까닭

데이터셋 보고서는 원본 사진을 서버에서 바로 분석하지만, 옷 등록 화면은 먼저 사진을 최대 3000픽셀로 줄이고 JPEG로 다시 저장한 다음 분석해요. 원본 사진을 서버가 한 번 줄이는 것과, 먼저 줄인 사진을 다시 줄이는 과정은 결과가 달라질 수 있어요.

실제로 ChArUco 격자에서 찍은 바지 사진은 원본 분석에서 너비가 **42.0cm**, 등록 화면을 거친 사진은 **47.3cm**였어요. 축소된 사진을 JPEG 압축 없이 PNG로 분석해도 47.3cm가 나왔습니다. 이 사례에서는 JPEG 압축보다 **분석 전에 사진을 축소한 것**이 직접적인 차이 원인이었어요. 그래서 등록 결과는 저장하기 전에 꼭 확인해야 해요.

## 3. 데이터셋 결과 페이지

`measure-dataset.html`은 `measure_dataset/` 안의 예시 사진 20장을 분석해요. 사진 이름에는 배경, 옷 번호, 줄자로 잰 너비와 길이가 들어 있어요. 이 페이지는 원본 파일을 직접 읽어 같은 배경 보정과 옷 측정 코드를 실행한 뒤, 줄자 기준값과 비교합니다.

데이터셋 보고서는 **예시 사진을 비교하는 실험 결과**예요. 실제 옷 등록 결과와 숫자가 항상 같다고 보장하지 않아요. 등록 화면과 실험 화면은 사진 크기와 저장 방식, 옷 종류별 기준을 전달하는 방법이 다를 수 있어요.

## 4. 사진과 기록은 어디에 저장되나요?

- 비교 실험의 사진과 결과는 서버 PC의 `server-data/experiments/` 아래에 회차별로 저장돼요.
- 옷장에 등록한 사진과 정보는 `server-data/garments/` 아래에 저장돼요.
- 실험 회차는 결과 페이지에서 다시 볼 수 있어요.
- 현재 저장은 서버를 실행한 PC 안에서 이뤄져요. 학교별 계정이나 원격 저장소는 연결되어 있지 않아요.

## 5. 정확하게 재려면 이렇게 해요

- A0 배경 종이를 100% 크기로 인쇄하고, 옷을 배경 위에 주름 없이 펼쳐요.
- 배경 표식과 옷의 네 끝이 모두 사진 안에 들어오게 해요.
- 휴대폰을 가능한 한 배경 위쪽에 두고, 그림자와 흔들림을 줄여요.
- 줄자로 잰 기준값을 적고, 자동 측정 선이 실제 옷의 위치에 놓였는지 확인해요.
- 색이 비슷한 옷, 접힌 옷, 표식이 잘린 사진은 결과가 틀릴 수 있어요. 이상하면 숫자를 고치거나 다시 촬영해요.

자동 분석의 신뢰도 숫자는 정답 확률을 보장하는 점수가 아니에요. AI가 옷 종류나 성별을 확실하게 알아내는 기능도 현재는 없어요. 이 시스템은 OpenCV 이미지 처리와 정해 둔 옷 종류별 기준을 이용한 **도움용 추정값**이에요.

## 낱말 풀이

- **픽셀:** 사진을 이루는 아주 작은 네모 점이에요.
- **기준값:** 줄자로 직접 재서 컴퓨터 결과와 비교하는 숫자예요.
- **원근 보정(평판화):** 기울어져 찍힌 배경을 정면에서 본 것처럼 펴는 일이에요.
- **윤곽:** 옷의 바깥쪽 테두리예요.
- **오차:** 줄자로 잰 기준값과 사진에서 잰 값의 차이예요. 오차가 작으면 두 숫자가 더 비슷해요.
- **OpenCV와 GrabCut:** 사진에서 배경과 옷을 구분하도록 돕는 이미지 처리 도구와 방법이에요. 스스로 옷의 종류나 성별을 모두 알아내는 AI는 아니에요.

## 6. 아직 구현되지 않은 요청

- 옷 등록 화면에서 점·격자·ChArUco·ChArUco 격자를 고르는 기능은 아직 없어요. 현재는 M4만 사용해요.
- 원본 사진의 크기를 유지해 분석하는 기능은 아직 없어요. 등록 사진을 3000픽셀로 줄이는 과정 때문에 값이 달라질 수 있어요.
- 옷장 카드에서 격자 배경을 지우고 옷만 보여 주는 기능은 아직 없어요.

이 항목들은 현재 동작 설명과 구별하기 위해 “아직 구현되지 않은 요청”으로 표시했어요.
