# 옷장 사진 로딩 개선 설계

## 목표

등록된 옷 사진, 특히 `데이터셋 2 크롭 티셔츠` 같은 기존 데이터셋 옷이 옷장에 빠르게 나타나게 한다. 원본 사진과 이미 저장한 측정값은 바꾸지 않는다.

## 현재 상태와 원인

옷 카드가 `/api/garments/<id>/thumbnail`을 요청한다. 현재 캐시가 없거나 마스크 파이프라인 버전이 달라지면 서버가 요청을 처리하는 도중 원본 사진을 다시 평탄화하고 YOLO·GrabCut으로 옷 영역을 찾은 뒤 투명 PNG와 썸네일을 만든다. 이 계산은 이미지 응답을 늦춘다. 새 옷 등록 중 생성 결과가 있으면 투명 PNG와 320px 썸네일을 함께 저장하지만, 기존 데이터셋 기록에는 이 파일이 없거나 오래된 기록이 있을 수 있다.

## 설계

- 원본 업로드 사진은 그대로 유지한다. 옷 분리 이미지와 작은 썸네일은 별도 캐시 파일로 둔다.
- 요청 처리 중 전체 이미지 분석을 반복하지 않는다. 서버 시작 또는 별도 준비 명령이 기존 옷의 빠진 썸네일을 만들고, 준비 중에도 목록의 이미지 응답은 기존 저장 이미지나 원본 사진으로 즉시 대체한다.
- 캐시 버전을 명시해 옷 분리 방법이 바뀔 때 재생성 대상을 확인할 수 있게 한다.
- 목록의 이미지는 `loading="lazy"`, `decoding="async"`를 유지하고, 필요한 크기의 썸네일 URL만 요청한다. 원본 전체 크기는 사용자가 상세/배경 포함 사진을 열 때만 불러온다.
- 배경 생성 작업의 실패는 해당 옷에만 기록하고 앱 시작과 옷 목록 API를 실패시키지 않는다. 다음 재시도 때 다시 준비할 수 있게 한다.

## 범위와 파일 경계

- `server.py`: 기존 썸네일 요청을 빠른 파일 응답으로 제한하고 캐시 준비 작업을 시작한다.
- `tools/garment_thumbnails.py` (신규): 저장된 옷의 썸네일 생성·버전 확인을 담당한다.
- `js/measurement/garmentCloset.js`: 기존 썸네일 우선 표시와 실패 시 원본 표시를 유지한다. 카드 DOM 생성 시 불필요한 재요청을 하지 않는다.
- `tests/`: 썸네일 캐시 적중, 캐시 없음 대체 응답, 재생성 실패 격리, 필요한 화면의 지연 로딩 동작을 검증한다.

## 성공 조건

- 캐시가 준비된 데이터셋 2 사진 요청은 YOLO/GrabCut 분석을 실행하지 않고 바로 응답한다.
- 캐시가 없는 사진도 무거운 분석 응답을 기다리는 빈 화면으로 남지 않고 기존 사진을 표시한다.
- 원본 사진 바이트와 등록된 치수 데이터는 준비 전후 동일하다.
- Python 표준 라이브러리와 이미 설치된 이미지 처리 코드만 사용한다. npm/pip 의존성을 추가하지 않는다.

## 제외

AI 상품 사진 생성, 계정 역할, 옷장 UI 재설계는 이 기능에 포함하지 않는다.
