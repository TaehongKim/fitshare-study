# Measure Dataset 자동 측정 파이프라인 설계

작성일: 2026-10-09
상태: 설계 명세 검토 대기

## 목적

`measure_dataset/`의 사진 20장을 반복 가능한 검증 자료로 사용해, 사진 방향을 바로잡고 실측 배경을 평판화한 뒤 옷 종류에 맞는 너비와 길이를 자동 추정하는 프로토타입을 설계한다. 결과에는 원본/보정 사진, 측정 위치, 추정 치수, 처리 성공 여부와 데이터 기준값 대비 오차를 함께 보여준다. 초등학생이 이해할 수 있도록 화면 안내를 쉬운 한국어로 쓴다.

## 확정 요구와 가정

- 폴더는 `point`, `cross`, `ChArUco`, `ChaArUco_Cross` 네 종류이고 각 5장, 총 20장이다. 실제 폴더의 `ChaArUco_Cross` 철자는 그대로 기록하며, 자료 설명에는 사용자가 부르는 `charuco_cross` 이름도 함께 적는다.
- 파일명은 `<배경 약자>_<옷 번호>_w<너비 cm>_h<길이 cm>.jpg` 형식이다.
- 사용자가 확인한 기준: 1~4번 상의/원피스는 `w=가슴 너비`, 5번 바지는 `w=허리 너비`; 모든 옷은 `h=기장`이다. 2번 크롭티셔츠와 4번 점퍼도 상의 기준을 쓴다.
- 옷 번호: 1 상의 외투, 2 흰 크롭티셔츠, 3 원피스, 4 점퍼, 5 바지.
- 사진 방향은 EXIF 정보를 반영해 픽셀 회전까지 정규화한다.
- 계정, 서버 API, 원격 사진 저장은 이번 범위에서 제외한다.
- 데이터에는 측정 치수 라벨이 있지만 픽셀 단위 옷 마스크나 측정점 주석은 없다. 따라서 이 데이터만으로 지도학습 모델을 학습했다고 주장하지 않는다.

## 현재 기준선

현재 배경 모서리 탐지기를 대표 사진 4장(`point/p_1`, `cross/c_1`, `ChArUco/ch_1`, `ChaArUco_Cross/chc_1`)에 확인했을 때 모두 실패했다. 그러므로 기존 간단 색상/외곽 규칙을 그대로 확장하는 대신, 배경 종류별 검출과 실제 20장 비교를 기준으로 개선한다.

## 구현 접근

### 사진 처리

1. EXIF 회전을 적용하고 디코딩한다.
2. 사진에서 선택된 배경 또는 인식된 배경 유형에 맞는 표식 검출기를 실행한다.
3. 유효한 네 모서리 또는 대응되는 평면 좌표가 확인되면 원근 변환으로 매트를 정면 보기로 보정한다.
4. 보정 결과에 옷 분할과 종류별 측정선을 구한다.
5. 결과 사진에 측정선을 겹쳐 보여주고 `w`, `h`, 신뢰도, 오류 이유를 함께 제공한다. 신뢰도가 낮으면 자동 치수를 확정값처럼 저장하지 않고 직접 확인 안내를 보여준다.

### 배경 처리와 라이브러리

브라우저에서 실행되는 OpenCV.js를 로컬 정적 파일로 포함하는 방식을 후보로 삼는다. 원근 보정 자체는 기존 코드와 재사용 가능성을 확인하고, OpenCV.js는 점/격자 특징 및 ChArUco 표식 검출처럼 기존 단순 색상/경계 규칙이 처리하지 못하는 부분에 한정한다. 패키지 관리자나 원격 CDN에 의존하지 않는다. 구현 계획 단계에서 사용하려는 빌드의 API에 ChArUco 바인딩이 실제 포함됐는지 작은 검증을 먼저 한다. 없다면 (a) 필요한 모듈만 넣어 직접 빌드하거나 (b) ChArUco를 별도 지원 단계로 분리하고 점/격자부터 구현한다. 검증되지 않은 API를 제품 코드에서 가정하지 않는다.

### 종류별 측정

- 1 상의 외투, 2 흰 크롭티셔츠, 4 점퍼: 겨드랑이 아래 가슴 너비와 옷의 기장.
- 3 원피스: 가슴 너비와 원피스 기장.
- 5 바지: 허리의 평평하게 잰 너비와 옆선 기장.
- 단순 외곽 사각형의 가로·세로를 의미 치수로 대신하지 않는다. 측정점을 찾을 수 없거나 흰 옷과 밝은 매트가 분리되지 않으면 실패 상태와 이유를 반환한다.

## 데이터 설명 및 결과 비교

`measure_dataset/README.md`는 폴더/약자, 파일명 읽는 법, 번호별 옷 유형과 너비 기준, EXIF 회전, 주석/표본 수 제한, 로컬 비교 실행 방법을 설명한다.

검증 화면 또는 도구는 모든 20장을 같은 파이프라인으로 처리하고 아래를 표로 표시한다.

- 사진별 배경/옷 번호, 라벨 w/h, 자동 w/h, 절대 오차, 성공/실패와 실패 이유
- 배경별 및 옷별 처리 성공률(전체 사진 수 기준)과 너비/길이 평균 절대 오차(MAE, 측정 성공 사진 기준 및 표본 수 병기)
- 보정/측정 결과를 확인할 수 있는 사진 오버레이

파일명 치수는 비교 기준으로만 사용하고 자동 처리 입력으로 사용하지 않는다. 프로토타입은 이 20장에 대한 재현 가능한 결과와 오차 보고를 제공하는 것이 목표다. 작은 데이터셋만으로 새 사진 전체에 대한 정확도를 보증하지 않는다.

## 파일 경계

- `measure_dataset/README.md`: 데이터 사전 및 검증 한계.
- `js/measurement/`: 현재 실측 모듈 안에서 사진 정규화, 보정, 종류별 측정, 비교 실행을 책임별로 분리한다. 구체 파일/함수는 구현 계획에서 기존 구조와 맞춰 확정한다.
- `measure/` 및 `css/`: 학생용 안내, 비교 결과 화면을 연결한다.
- `tests/`: 데이터 파일명 파싱, 각 종류 기준값, 이미지 방향/평판화/측정 실패, 전체 20장 비교 결과의 회귀 확인을 추가한다.
- `Handspff/진행상황.md`: 세션에서 완료된 작업과 다음 할 일을 기록한다.
- 공통 `js/app.js`, 추천/랭킹 모듈은 수정하지 않는다.

## 명세 자체 검토

- 파일명 기준 치수는 비교에만 사용되며 자동 측정 로직에 입력되지 않는다.
- 성공률은 해당 그룹 전체 사진을 분모로 하고, MAE는 실제 자동 측정에 성공한 사진만 대상으로 하며 개수를 함께 표시한다. 실패 사진은 오차 평균에서 빠지더라도 성공률과 실패 이유에 남는다.
- 이번 단계에서는 서버 저장이나 일반 AI 학습을 추가하지 않는다.

## 완료 조건

1. 20개 파일 모두 올바르게 읽혀 배경/옷 ID/w/h 라벨로 해석된다.
2. 목표는 20장 모두 자동 보정과 종류별 치수 계산 결과를 내는 것이다. 반복 개선 후에도 실패가 남으면, 통과했다고 보고하지 않고 사진별 원인과 남은 한계를 결과에 기록한다.
3. EXIF 방향이 반영되며 잘못된 파일이나 불러올 수 없는 이미지에서 앱이 중단되지 않고 설명 가능한 오류를 낸다.
4. 네 배경 유형별로 검출/보정 결과가 비교되며, 실패는 감추지 않는다.
5. 옷 종류에 따라 올바른 의미 치수(상의/원피스 가슴 너비, 바지 허리 너비, 기장)를 계산하고 사진 위에 표시한다.
6. 모든 샘플에 대해 오차를 계산하고 배경별·종류별 결과를 제시한다. 기대한 정확도를 달성하지 못한 사진을 성공으로 꾸미지 않는다.
7. 테스트는 정상/경계/오류 사례를 포함하고 기존 실측 테스트가 통과한다.
8. `Handspff/진행상황.md`에 변경과 테스트를 기록한다.

## 범위에서 제외

- 계정, 원격 API, PostgreSQL, 서버 저장소.
- 이 데이터만으로 일반화된 AI 학습 또는 새 촬영 사진에 대한 정확도 보증.
- 사용자가 직접 촬영한 모든 새 사진에서 무조건 자동 측정 성공을 약속하는 것.
- 추천/랭킹 모듈 변경.

## 주요 위험과 대응

- 흰 크롭티셔츠와 흰 배경이 비슷해 옷 분리가 실패할 수 있다. 신뢰도와 실패 상태를 노출하고, 추가 배경 대비 자료 또는 수동 보정이 필요하다고 기록한다.
- 옷 외곽 상자만으로 가슴 너비/허리 너비를 알 수 없다. 종류별 측정 기준선을 별도로 찾아야 하며, 데이터 5종류별 표본이 각각 4장뿐이라 일반화 검증은 제한된다.
- 사진에 매트 가장자리나 일부 표식이 잘렸을 수 있다. 보정이 불가능하면 억지로 치수를 계산하지 않고 해당 사진을 실패로 집계한다.
- 공식 OpenCV.js 빌드 간 노출 API가 다를 수 있다. 라이브러리 선택/포함 전에 실제 API 스모크 테스트를 통과시킨다.
