사진 속 옷을
어떻게 재는 걸까요?

컴퓨터는 사진 속 기준판을 자처럼 이용해 사진을 반듯하게 고친 다음, 옷으로 보이는 픽셀을 모으고, 옷의 종류에 맞는 위치에서 너비와 기장을 계산해요.

한 문장으로: 기준판을 자로 삼아 사진을 바로잡고, 옷의 색과 모양을 찾아 표시한 뒤, 픽셀 길이를 실제 센티미터(cm)로 바꿔요.
  • 실측 순서
  • 실제 코드
  • 호수 자동 매핑
  • 아직 못 하는 것
  • 정확도와 확인

큰 순서부터 알아봐요

사진 보정부터 cm 계산까지 다섯 단계예요

사진을 찍기 전에 옷을 사람이 먼저 펴 놓아요. 컴퓨터가 하는 “사진 평탄화”는 옷을 다림질하는 일이 아니라, 비스듬한 사진을 종이를 정면에서 본 것처럼 고치는 일이에요.

옷과 기준판을 함께 찍어요

옷을 기준판 가운데에 놓고 가능한 한 펴요. 기준판의 네 모서리와 표식이 사진에 다 나오게 해요.

사진에서 기준판을 찾아 바로잡아요

점·격자·ChArUco 표식을 찾아 실제 기준판 모양에 맞춰요. 비스듬한 사각형을 반듯한 A0 판처럼 변환해요.

옷으로 보이는 곳을 골라요

색과 이어진 모양을 살펴 옷 픽셀을 흰색, 배경을 검은색으로 표시해요. 이 흑백 지도를 마스크라고 해요.

종류별 규칙으로 너비와 기장을 찾아요

옷 종류에 따라 미리 정한 높이 비율에서 너비를 재고, 옷의 위아래 끝을 기준으로 기장을 구해요.

픽셀을 cm로 바꾸고 사람이 확인해요

A0 기준판의 알려진 길이로 픽셀을 cm로 환산해요. 결과 사진에 칠해진 옷 영역과 선이 맞는지 눈으로 보고, 이상하면 다시 찍거나 숫자를 고쳐야 해요.

사진과 옷은 다르게 다뤄요. 프로그램은 사진의 기울기를 바로잡을 수 있지만, 옷 주름을 자동으로 펴지 못해요. 옷을 당겨 놓은 상태도 원래대로 되돌릴 수 없어요.

배경은 커다란 자예요

배경 무늬로 사진 속 크기를 알아내요

네 기준판은 무늬와 찾는 방법이 달라요. 사진에서 찾은 점·선·표식의 위치를 기준판의 알려진 좌표와 짝지어 보정합니다. 아래 사진은 실제 실험에 사용한 기준판입니다.

M1 · 점 표식

회색조와 임계값 처리로 어두운 점을 분리한 뒤 cv2.connectedComponentsWithStats로 이어진 픽셀을 점 덩어리로 묶어요. 점 크기·위치 조건으로 후보를 고르고 외곽 모양을 기준 좌표에 대응합니다.

  • 핵심 함수: _component_mask, _detect_dot_mat, cv2.getPerspectiveTransform
  • 점들의 바깥 윤곽과 간격으로 판의 위치와 방향을 계산해요.

M2 · 십자 격자

cv2.Canny로 선의 가장자리를 강조하고 cv2.HoughLinesP로 긴 선분을 찾아요. 방향이 비슷한 선을 가로·세로로 묶고 cv2.fitLine과 _line_intersection으로 교차점을 계산합니다.

  • 핵심 함수: _detect_cross_mat, _cluster_grid_lines, cv2.Canny, cv2.HoughLinesP
  • 교차점과 판의 경계를 기준 좌표에 맞춰 원근을 펴요.

노란 테두리: 사진의 오른쪽 위 가장자리에서 찾은 ID 31

M3 · ChArUco 표식

cv2.aruco.ArucoDetector.detectMarkers가 표식의 네 모서리와 ID를 찾아요. ID는 QR 번호가 아니라 DICT_4X4_1000 사전에서 무늬를 구분하는 ArUco 표식 번호예요.

  • ID는 위치나 순서를 뜻하지 않아요. data/charuco_marker_maps.json에서 이 판의 ID에 해당하는 네 모서리 기준 좌표를 찾는 열쇠예요.
  • 사진에서 실제로 찾은 ID 31 위치를 위 그림에 노란 테두리로 표시했어요. 표식 번호를 기준표에서 찾아 좌표로 연결합니다.
  • cv2.findHomography와 RANSAC이 잘못 짝지어진 표식을 걸러요.

노란 테두리: 사진의 왼쪽 아래 가장자리에서 찾은 ID 243

M4 · ChArUco 격자

검출기는 M3와 같지만 격자형 판의 ID 배치와 기준 좌표표는 별개예요. M4 전용 좌표표에서 ID마다 기준판의 네 모서리를 찾아 사진 좌표와 연결합니다.

  • 핵심 함수: ArucoDetector.detectMarkers, cv2.findHomography, RANSAC
  • 사진 왼쪽 아래에 검출한 ID 243을 표시했어요. ID 번호만으로 위치를 추측하지 않고, M4 기준표에서 좌표를 조회합니다.

M1·M2는 점이나 선에서 대응점을 계산하고, M3·M4는 검출한 ID로 기준 위치를 조회해요. 앞의 두 방식은 대응점으로 cv2.getPerspectiveTransform 또는 cv2.getAffineTransform을 구하고, ChArUco는 여러 표식 대응점으로 cv2.findHomography를 구합니다. 마지막에는 cv2.warpPerspective 또는 cv2.warpAffine으로 사진을 변환해요.

입력 사진을 줄이고 보정 결과를 통일하는 이유

원본 사진은 4000×3000픽셀입니다. 표식을 찾기 전 긴 변이 최대 1000픽셀이 되도록 줄이고, 찾은 좌표를 이용해 A0 기준판을 600×848픽셀 캔버스에 맞춰요. 실제 크기 84.1×118.9cm에 맞춘 공통 좌표판이라 사진마다 픽셀과 cm의 관계를 같은 기준으로 계산할 수 있습니다.

옷 마스크 계산에서는 보정 사진을 다시 긴 변 최대 600픽셀로 줄여요. 따라서 보정 출력 기준은 약 0.140cm(1.4mm)/px이고, 마스크 분석 영상은 약 424×600픽셀로 약 0.198cm(2.0mm)/px입니다. 출력 이미지 해상도와 옷 경계를 분석하는 해상도는 같지 않아요.

입력과 마스크 크기 제한은 처리할 픽셀 수를 줄여 계산량과 메모리 사용을 낮추는 효과가 있습니다. 이는 코드의 크기 제한을 바탕으로 한 해석입니다. 축소 과정에서 작은 경계 정보가 사라질 수도 있으므로, 숫자를 크게 하면 항상 정확도가 좋아진다고 할 수 없어요.

고해상도 변경 전후를 실험 사진 20장으로 비교했어요

현재 설정은 20/20장 성공, 너비·기장 평균 절대 오차(MAE)는 2.9cm / 4.1cm였어요. 입력·보정 출력·마스크 크기를 모두 두 배로 한 설정은 20/20장 성공했지만 오차가 5.7cm / 7.4cm로 커졌습니다. 입력 축소 한도만 1000에서 2000픽셀로 올리고 출력·마스크 크기는 그대로 둔 설정은 너비 오차 2.7cm, 기장 오차 5.7cm였어요.

그래서 현재 해상도를 유지합니다. 이 20장 비교에서는 전체적으로 더 정확해지지 않았어요. 측정 오차에는 표식 검출뿐 아니라 옷 마스크와 측정선 선택도 영향을 줍니다. 이 결과는 현재 실험 사진의 결과이며 모든 옷과 촬영 조건을 보장하지 않아요.

중요: 아무 바닥 무늬나 자가 되는 것은 아니에요. 무늬의 간격이나 표식 위치, 기준판의 실제 크기를 미리 알아야 해요. 표식이 가려지거나 판이 사진 밖으로 잘리면 바로잡기 어렵고, 옷이 구겨져 있으면 사진만 반듯하게 고쳐도 옷 주름은 펴지지 않아요.

실제 프로그램은 이렇게 해요

아래는 실제로 사용하는 함수와 계산을 이해하기 쉽게 짧게 보여 준 예시예요. 초록색으로 시작하는 줄은 초등학생을 위한 설명 주석이에요.

파랑: 변수, 값을 담는 이름 보라: 함수, 일을 하는 도구 노랑: if 같은 약속 낱말 분홍: 정해 둔 값·상수 초록: 사람이 읽는 설명

1. 기준 표식을 찾아 사진을 반듯하게 펴기

서버의 OpenCV 코드가 표식 좌표와 실제 판 좌표를 맞춥니다.

corners, ids, _ = detector.detectMarkers(gray)
# 사진에서 모양과 번호가 있는 표식을 찾아요.

if ids is None:
    raise ValueError("표식을 못 찾았어요")

matrix, inliers = cv2.findHomography(
    source_points, target_points, cv2.RANSAC, 3.5
)
# 사진 속 점을 종이 위의 자리로 옮기는 계산표를 만들어요.

flattened = cv2.warpPerspective(
    image, matrix, (OUTPUT_WIDTH, OUTPUT_HEIGHT)
)
# 계산표를 따라 사진을 반듯한 A0 모양으로 바꿔요.
detector.detectMarkers
OpenCV 도구예요. 사진에서 ArUco 표식의 네 모서리와 번호를 찾아요.
gray
색을 회색 밝기 하나로 바꾼 사진이에요. 표식의 테두리를 찾기 쉽게 해요.
corners / ids
표식 모서리의 사진 좌표와 표식 번호들이에요.
detector / _
detector는 표식을 찾는 도구이고, _는 이번 계산에서 쓰지 않는 결과를 담아 둔 이름이에요.
source_points / target_points
사진에서 찾은 점과, 반듯한 기준판에서 같은 점이 있어야 할 자리예요.
cv2.findHomography
비스듬한 사진 좌표를 종이 좌표로 바꾸는 계산표(matrix)를 찾아요.
inliers
여러 점 가운데 계산 결과와 잘 맞는 점들이에요. RANSAC이 이상한 점을 거를 때 도와요.
cv2.RANSAC / 3.5
이상한 점을 걸러내는 방법과, 맞는 점으로 볼 때 허용하는 오차 범위예요.
cv2.warpPerspective
찾아낸 계산표를 실제 사진에 적용해 원근을 펴는 함수예요.
flattened
원근 보정이 끝나 반듯해진 사진이에요.

warpPerspective는 사진의 원근을 바꾸는 함수예요. 사진이 비스듬하면 가까운 쪽과 먼 쪽의 크기 차이도 함께 보정할 수 있어요.

2. 옷과 배경을 나누기

옷 안쪽일 것 같은 곳과 배경일 것 같은 곳을 알려 준 다음 색과 경계를 살펴요.

cv2.grabCut(
    working, labels, None,
    background_model, foreground_model,
    3, cv2.GC_INIT_WITH_MASK
)
# 컴퓨터에게 "이쪽은 옷일 것 같아" 하는 힌트를 줘요.

binary = (labels == cv2.GC_FGD) | (labels == cv2.GC_PR_FGD)
# 옷이라고 생각한 칸은 참, 배경은 거짓으로 표시해요.

binary = cv2.morphologyEx(binary, cv2.MORPH_CLOSE, kernel)
# 옷 마스크에 난 작은 구멍을 메워요.
working
분석하기 알맞은 크기로 줄인 사진이에요.
labels
각 픽셀이 배경인지 옷인지, 또는 아직 잘 모르는지 적어 둔 표예요.
cv2.GC_FGD / cv2.GC_PR_FGD
옷이라고 확실하거나 옷일 가능성이 높다고 표시하는 두 가지 표시예요.
background_model / foreground_model
배경과 옷의 색 특징을 컴퓨터가 기억하는 임시 상자예요.
cv2.grabCut
사진의 색과 경계를 보고 옷과 배경을 나누는 OpenCV 함수예요.
binary
옷 픽셀은 1, 나머지는 0처럼 표시한 흑백 지도예요.
cv2.morphologyEx
작은 틈을 메우거나 작은 점을 정리하는 모양 처리 도구예요.
kernel
작은 구멍이나 점을 살펴볼 때 쓰는 작은 모양 도장 같은 기준이에요.
CIELAB
색을 밝기와 색 차이로 비교하기 편하게 나타내는 색 공간이에요.

이 방식은 사진을 보고 색과 가까운 픽셀을 나누는 OpenCV 처리예요. 옷 안쪽 색은 CIELAB 색 공간에서 비교해 밝기와 색 차이를 살펴요. YOLO나 SAM 같은 학습된 인공지능이 현재 기본 실측을 대신하는 것은 아니에요.

3. 옷 종류에 맞춰 잴 줄 고르기

마스크에서 가로 폭을 계산하고, 종류별 비율로 너비 선 위치를 정합니다.

base_threshold = maximum_span * profile.get("lengthSpanRatio", .55)
active_rows = np.flatnonzero(base_spans >= base_threshold)
top = int(active_rows[0])
bottom = int(active_rows[-1])
# 옷의 폭이 충분한 가로줄만 골라 위와 아래 끝을 정해요.

target_y = int(width_top + width_height * profile["widthRatio"])
# width_top에서 옷 높이의 widthRatio만큼 내려온 곳이에요.

width_pixels = float(np.median(valid_spans))
# 그 높이 주변의 폭 중간값을 사용해 작은 흔들림을 줄여요.
base_spans
마스크의 각 가로줄에서 옷이 차지하는 폭을 모은 목록이에요.
maximum_span
그중 가장 넓은 가로줄의 픽셀 수예요.
profile
상의·바지처럼 옷 종류마다 다른 비율 규칙표예요.
lengthSpanRatio / widthRatio
기장 끝과 너비선을 찾을 때 쓰는 옷 종류별 비율이에요.
base_threshold
기장 끝을 고를 때 기준으로 삼는 최소 가로 폭이에요.
active_rows
옷의 위아래 끝을 정할 만큼 폭이 충분한 가로줄 번호들이에요.
width_top / width_bottom
너비선을 고르기 위해 만든 높이 범위의 맨 위와 맨 아래 줄이에요.
width_height
width_bottom - width_top으로 구한 범위의 높이예요. 이 높이에 비율을 곱해요.
target_y
width_top + width_height × widthRatio로 정한 너비선의 세로 위치예요. 봉제선을 직접 찾은 위치는 아니에요.
top / bottom
기장에 쓸 가장 위와 아래의 가로줄 번호예요.
np.flatnonzero / int
조건에 맞는 줄 번호를 찾고, 그 번호를 정수로 바꾸는 도구예요.
np.median / float
폭의 가운데 값을 구하고, 소수점 계산이 가능한 숫자로 바꾸는 도구예요.
valid_spans / width_pixels
너비선 주변에서 쓸 수 있는 폭 목록과, 그 폭의 대표 픽셀 값이에요.

옷 종류별 비율 지점에서 너비를 재요

기준은 옷으로 고른 영역의 위쪽부터 아래쪽까지 높이예요. 높이가 100px이면 40%는 위에서 40px 내려온 곳이에요.

여기서 profile은 옷 종류별 규칙표예요. width_top과 width_bottom 사이의 높이를 계산한 뒤, 그 높이에 widthRatio를 곱해 너비선을 놓아요. 이 방법은 단순한 위치 추정이며 “겨드랑이 선”을 눈으로 찾는 방법은 아닙니다.

4. 픽셀 길이를 실제 cm로 환산하기

A0 종이의 실제 가로·세로 크기를 사진 픽셀에 적용합니다.

cm_per_pixel_x = A0_WIDTH_CM / OUTPUT_WIDTH
cm_per_pixel_y = A0_HEIGHT_CM / OUTPUT_HEIGHT
# 종이의 1픽셀이 실제로 몇 cm인지 방향별로 구해요.

width_cm = width_pixels * cm_per_pixel_x
length_cm = garment_height * cm_per_pixel_y
# 사진 속 픽셀 길이에 cm 값을 곱해 실제 길이를 구해요.
A0_WIDTH_CM / A0_HEIGHT_CM
A0 기준판의 실제 가로 84.1cm와 세로 118.9cm예요.
OUTPUT_WIDTH / OUTPUT_HEIGHT
반듯하게 고친 사진의 가로·세로 픽셀 수예요.
cm_per_pixel_x / cm_per_pixel_y
가로 또는 세로 방향의 픽셀 하나가 몇 cm인지 나타내요.
width_pixels / garment_height
사진에서 잰 너비와 기장의 픽셀 수예요.
width_cm / length_cm
픽셀 계산을 마치고 얻은 너비와 기장의 cm 값이에요.

실제 코드에서는 분석 이미지 크기가 달라질 때를 고려해 픽셀 비율을 한 번 더 반영해요. 가로와 세로의 픽셀 크기가 같지 않을 수 있어서 두 방향을 따로 계산합니다.

마지막으로 기준을 확인해요

자동으로 그은 선이 원하는 위치인지 살펴봐요

사람이 옷을 잴 때

상의는 겨드랑이 아래처럼 정해 둔 기준에서 너비를 재는 경우가 많아요. 판매처마다 측정 위치가 다를 수 있어 안내를 확인해야 해요.

프로그램이 잰 결과

앞의 그림처럼 마스크 높이의 비율로 너비선을 골라요. 겨드랑이나 봉제점을 찾은 결과가 아니므로, 오버레이를 보고 원하는 위치인지 확인해 주세요.

측정값의 뜻: 너비는 옷을 바닥에 펼쳤을 때의 좌우 길이이고, 기장은 옷 영역에서 찾은 위·아래 끝 사이 길이예요. 둘레나 사람이 입었을 때의 몸 치수는 아닙니다.

잰 치수를 호수와 비교해요

옷의 너비와 기장으로 아동복 호수를 바로 알 수 있을까요?

치수를 입력하면 옷 종류별 참고표와 비교해 국내에서 쓰는 키 호수 하나를 바로 골라요. 호수 숫자는 아이의 키를 가리키는 이름이고, 옷의 길이와 같지 않아요. 자동 선택 뒤에는 호수를 직접 바꿀 수 있어요.

확인한 한국 기준 자료

한국산업표준에는 KS K 0052 「유아복의 치수」, KS K 9402 「남자 아동복의 치수」, KS K 9403 「여자 아동복의 치수」 기준이 있어요. 한국표준정보망은 세 표준 모두 2025년 9월 개정된 것으로 안내해요. 적용 연령과 옷 종류가 표준마다 달라요.

자료알려 주는 내용알려 주지 않는 내용
KS K 0052 영아부터 취학 전 유아 의류 치수 기준 초등학생 옷까지 포함하는 단일 호수표
KS K 9402·9403 각각 만 7~12세 남자·여자 아동복 치수 기준 사진으로 잰 옷의 펼친 너비·기장으로 브랜드 호수를 판정하는 공식

출처: KS K 0052 유아복, KS K 9402 남자 아동복, KS K 9403 여자 아동복.

자동 매핑은 이렇게 해요

옷 종류를 고르고 사진에서 확인한 너비·기장을 입력하면 내장 참고 치수표에서 너비와 기장이 가장 가까운 90~160호 하나를 바로 선택해요. 선택된 호수는 바로 아래 상자에서 직접 바꿀 수 있어요.

내장 너비·기장 값은 FitShare가 정한 임시 참고값이에요. 공식 KS 변환표나 실제 상품 치수 통계가 아니며, 여러 브랜드의 옷을 재어 검증한 값도 아니에요. KS 호수는 아이 키 기준이라 옷 실측만으로 아이에게 맞는 크기를 보장할 수 없어요. 브랜드와 디자인에 따라 다르니 상품을 고를 때 판매처의 안내와 아이의 키도 확인해 주세요.

사진에서 잰 옷 치수

이전 단계에서 확인한 결과를 cm 단위로 입력해요.

자동 호수는 참고용이에요. 자동으로 선택한 값은 옷 실측과 내장 참고표의 근접값이에요. KS의 공식 변환 결과나 아이에게 잘 맞는다는 보장은 아니에요. 판매처 안내와 아이 키를 함께 확인하고 필요하면 호수를 직접 바꿔 주세요.

현재 한계와 다음에 필요한 절차

아직 프로그램이 못 하는 것도 있어요

  • 옷을 직접 펴 주지 않아요. 접힌 소매, 겹친 옷감, 심한 주름은 촬영 전에 사람이 펴야 해요.
  • 겨드랑이·어깨·밑단의 봉제점을 직접 찾지 않아요. 이런 점을 알아내는 별도 기준점 찾기와 사람이 위치를 고치는 절차가 필요해요.
  • 사진이 잘 찍혔는지 전부 확인하지 않아요. 네 모서리가 보이는지 확인하는 일부 검사는 있지만, 흐림·그림자·주름을 모두 판별하지는 못해요.
  • 마스크가 괜찮아 보여도 잴 위치가 맞다는 뜻은 아니에요. 현재 confidence는 주로 마스크 면적을 바탕으로 해요. “90% 확률로 정확하다”는 뜻이 아니에요.
  • 옷 종류별 기준 위치를 줄자 측정과 더 비교해야 해요. 어깨부터 밑단까지인지, 목점부터 밑단까지인지 팀에서 먼저 통일해야 해요.
  • 여러 조건의 새 옷으로 시험해야 해요. 밝고 어두운 옷, 무늬 있는 옷, 주름진 옷, 다른 카메라와 조명에서도 기준 줄자와 비교해야 해요.

실험 숫자를 바르게 읽어요

반복해서 잘 됐다고 모든 옷에서 정확한 건 아니에요

진행 기록에는 20장 사진을 방법마다 100번씩 다시 분석한 실험이 있어요. 같은 사진을 여러 번 분석하는 것은 결과가 일정한지 확인하는 데 도움이 되지만, 서로 다른 옷 2,000벌을 시험했다는 뜻은 아니에요.

그 시험 사진에서 항상 원근 보정을 한 방법의 평균 절대 오차는 너비 2.94cm, 기장 4.13cm였어요. 이 숫자는 그 사진 모음의 결과이지, 모든 옷에서 보장하는 정확도가 아니에요.

사람이 마지막으로 확인해요. 색칠된 옷 영역이 옷 밖으로 새지 않았는지, 가슴·허리 선이 원하는 자리에 있는지, 기장 시작과 끝이 맞는지 확인하고 저장하세요.
